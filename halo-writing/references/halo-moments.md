# Halo 瞬间发布

仅用于 `content_type: moment`。沿用主技能的聊天、成稿、真实配图、审阅和确认流程；这里定义瞬间的连接与提交方式，不将瞬间当作文章 Post。

## 前提与能力发现

站点需要安装并启用 [瞬间插件](https://github.com/halo-sigs/plugin-moments) 和官方 MCP Server。瞬间插件会向官方 MCP 提供工具，还需在当前访问密钥中选择允许调用的工具；客户端重新发现后才可使用。

官方说明列出 `PluginMoments__list_moments`、`PluginMoments__get_moment`、`PluginMoments__create_moment`、`PluginMoments__delete_moment`。这些是识别能力的参考，实际名称、版本、输入和输出以当前 MCP 工具目录为准。普通写作只需要读取与创建，加上通用附件上传能力，不要求删除权限。

没有瞬间工具时，说明尚未获得该能力，并指出需要核实瞬间插件、MCP 工具授权及客户端刷新；继续完成本地稿件和配图。不自行安装生产插件、扩大权限，也不调用文章工具作为替代。

## 草稿与真实发布格式

当前官方 [MCP 工具实现](https://github.com/halo-sigs/plugin-moments/blob/main/src/main/java/run/halo/moments/mcp/MomentMcpToolProvider.java) 中，`create_moment` 会直接创建已审核的瞬间，是发布操作，不是保存草稿：

- `content` 是纯文本，不是 Markdown 或任意 HTML。确认前准备实际将提交的纯文本预览，将 Markdown 标记和链接转换为可读文本，不能默默丢失含义或把 front matter 当正文。
- 配图通过 `media` 的图片条目提交，例如类型 `PHOTO` 与真实可访问的 `url`。不把本地路径或 Markdown 图片语法塞进纯文本来代替上传。
- `tags` 是瞬间自身的标签字符串，不是文章标签资源 ID。没有文章专有的标题、分类、摘要、封面或 slug 参数。
- 可见性以用户选择及已审阅设置为准，首次未指定时在审阅中明确显示拟用值；不能把 `PRIVATE` 当作「未发布草稿」。

以上描述以已查阅版本为依据；连接时仍核对实际 schema。后续版本如果提供独立草稿能力，仅在明确支持并获草稿授权时使用；否则草稿保存在本地 `moments/<local-id>/moment.md`，不调用创建工具。

## 确认后提交

1. 从原稿、交接和状态中恢复 `content_type: moment`，核对站点、审阅过的纯文本、标签、配图顺序和可见性。没有本轮发布授权时停留在本地审阅阶段。
2. 检查是否已有该任务的瞬间远端 ID 或上次提交结果。已有结果先回读；没有结果时结合当前任务记录排查是否已经创建，不按文章 slug 查重。
3. 在发布授权范围内上传缺少的配图，检查返回的真实附件链接；所有预期图片就绪后才提交瞬间。复用已核实的附件映射，不重复上传。
4. 对新瞬间调用实际发现的创建工具一次，传入确认后的正文、媒体、标签和可见性。创建本身即发布，不再调用文章的发布状态工具。
5. 保存服务器返回的瞬间资源 ID，读取该瞬间，按返回的实际格式核对文本含义、标签、媒体链接/顺序和可见性；返回内容可能是转义后的 HTML，不与提交的纯文本做未经规范化的字节比较。
6. 返回真实 permalink；没有返回链接时，从已验证的站点页面发现，不猜测 URL。MCP 成功但主题页面不支持瞬间时，区分「对象已创建」与「前台可查看」，说明实际状态。
7. 更新 `halo-state.json`：`content_type: moment`、站点、远端 ID、实际链接、提交内容摘要哈希和附件映射。没有成功证据时不标记已发布。

创建请求超时或返回结果不确定时，先用列表/读取工具核实近期同一作者的正文和媒体是否匹配，再判断是否重试；存在多个候选或无法排除已经创建时停止写入，避免重复发布。

## 已发布瞬间的修改

已查阅版本没有独立的瞬间更新 MCP 工具。若用户要求修改已发布瞬间，先检查当前版本是否增加了更新能力；没有就说明缺口，保留改稿，供用户选择受支持的后续方式。不偷偷删除重建、不创建第二条冒充修改，也不转发为文章。删除授权与本技能的普通发布授权不同。
