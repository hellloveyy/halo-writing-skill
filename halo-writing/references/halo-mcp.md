# Halo 官方 MCP 接入

本技能首选 [Halo 官方 MCP Server](https://www.halo.run/store/apps/app-ybv96zol)（[源码](https://github.com/halo-dev/plugin-mcp-server)）。该插件提供远程 Streamable HTTP MCP，支持文章查询、读取、创建、更新、发布与附件上传。要求 Halo 2.26.0+ 和生产 HTTPS；实际安装时核对当前版本要求。

这是安装在 Halo 服务端的插件，不需要另写一个发布服务或在 Codex 插件目录中找到同名条目。技能保留用户的写作习惯和最后确认规则，MCP 提供实际操作工具。

## 首次接入

1. 先检查站点是否已安装并启用官方 MCP Server；若已配置可用连接，复用它。
2. 未安装时，在 Halo 后台应用市场找到发布者为 Halo 的「MCP Server」。用户已授权安装与连接时完成配置；仅讨论方案不代表授权修改生产插件设置。
3. 由站点超级管理员打开「工具 → MCP 服务」，为这台 Codex 创建访问密钥，选择文章查询、读取、创建、更新、发布，以及所需的分类/标签查询和附件上传工具。发布工作流不要求删除文章或附件权限。
4. 使用下面的 macOS 钥匙串方式，或将密钥安全配置为本机的 `HALO_MCP_TOKEN` 环境变量。不发送到聊天，不写入 Git。它是 MCP 专用访问密钥，不是「个人令牌」中的 REST PAT。
5. 使用后台提供的客户端配置接入。地址通常为 `https://你的站点/mcp`，以后台实际显示地址为准。未验证连接时不声称端点已启用。

## Codex 配置模板

官方支持将以下配置合并到用户 `~/.codex/config.toml`，或可信项目的 `.codex/config.toml`。有现有同名配置时先检查并保留其他服务器，不能覆盖整个文件。

```toml
[mcp_servers.halo]
url = "https://blog.example.com/mcp"
bearer_token_env_var = "HALO_MCP_TOKEN"
```

将示例域名换成实际站点。配置只引用环境变量名称，不包含密钥。Codex 客户端进程必须能读取该变量；在终端设置变量不保证已经运行的桌面进程能看到。按实际启动环境处理变量可见性，连接缺失时再检查或重启客户端。诊断只报告认证方式是否符合预期和连接状态，不能回显字段原值或令牌。

也可以从桌面版的 MCP 服务器设置添加 Streamable HTTP 连接；界面入口以当前客户端为准。[Codex 官方 MCP 文档](https://developers.openai.com/codex/mcp/)

### macOS 重启后自动认证

也可使用 macOS 登录钥匙串保存密钥，让 Codex 的 `http_headers_helper` 在连接时读取并返回认证头。此方式无需持久化全局环境变量；配置中用 helper 替换 `bearer_token_env_var`，避免旧环境变量优先于钥匙串凭据。helper 的路径按本机安装位置填写，不将其他电脑的绝对路径直接复制过来。

读取器 [keychain_headers.py](../scripts/keychain_headers.py) 和安装器 [install_macos_helper.py](../scripts/install_macos_helper.py) 随技能分发，无第三方 Python 依赖。使用 Python 3.9+，按实际技能安装位置执行，`--site` 使用用户的站点：

```text
python3 <技能安装目录>/scripts/install_macos_helper.py --site https://blog.example.com
```

安装器把读取器复制到稳定的 `$CODEX_HOME/bin/`（默认 `~/.codex/bin/`），文件名为 `halo_writing_keychain_headers.py`，并输出不含密钥的配置及保存密钥命令。不同内容的同名读取器已存在时会拒绝覆盖，应先检查备份。脚本不会修改 TOML、读取/保存密钥或访问网络。

1. 合并输出的 `[mcp_servers.halo]` 段落到实际 Codex 配置文件。已存在同名段落时编辑它，不重复添加；保留其他服务器及无关设置。
2. 使用输出的 `http_headers_helper`，移除该段落旧的 `bearer_token_env_var` 和静态 Authorization 设置。配置中只有程序路径与钥匙串身份，不包含密钥。
3. 在真实终端执行输出的 `security add-generic-password ... -w` 命令，按提示输入密钥；`-w` 放在最后，输入不会显示或进入命令历史。
4. 重新打开 Codex，先只读验证文章和附件列表，不用发测试文章。

钥匙串 service 默认为 `codex.halo.<站点主机名及端口>`，account 默认为 `halo`，由安装器输出具体值；可用 `--service`、`--account` 显式设置。读取器通过同名参数读取相应记录，不能混用其他站点的密钥。

helper 只应向 Codex 的凭据管道输出认证头。不要直接在对话工具中运行它并显示原始输出；诊断时在进程内捕获并检查，不将任何认证字段原值发送到聊天/日志。钥匙串尚未存入密钥、未解锁或不允许读取时，应给出不含密钥的明确错误。

钥匙串内容跨重启保留，但密钥到期、被撤销或轮换后仍需更新。配置完成不代表已经保存密钥或验证了 MCP 连接。换电脑需分别配置本机钥匙串及 helper。

## 验证与调用

- 检查 MCP 初始化和实际工具目录，再调用只读的文章查询工具，验证与目标站点的连接。只读查询成功不等于发布权限也已授权。
- 从返回的工具名、说明和输入 schema 选择查询、正文更新、附件上传和发布能力，不猜工具名或参数。安装新工具不会自动将其加入已有访问密钥的允许列表。
- 附件上传按工具支持的内容编码、大小限制或可访问 URL 传输；远程服务无法直接打开这台电脑的绝对路径。大图先处理到工具允许范围，不能忽略上传失败或为传文件私自部署临时公开文件服务。
- 沿用 Halo 配置的附件存储策略和分组。接收真实附件永久链接后再替换发布副本中的本地引用，不能推算链接。
- 新文章先保持为草稿；用户确认发布后再调用发布工具。若创建工具有自动发布参数，按当前授权显式设置，不能依赖默认值。明确获准直接发布时可以完成草稿创建、上传和发布这一整套流程，不重复确认每个中间步骤。
- 更新时根据实际 ID 查找同一篇文章，保留原 slug、日期和其他无关设置。提交前检查线上是否有其他修改；超时后回读状态，避免重复创建。
- 完成后回读文章、发布状态和正文，检查实际文章页面及图片，再更新本地 `halo-state.json` 并返回实际链接。

密钥失效或工具缺失时说明是连接、认证还是工具授权问题；不要自行轮换密钥、扩大权限或改用 REST 规避限制。保留本地稿件和已确认的远端结果，先处理具体阻碍。

## 换电脑

新电脑同步技能和本地稿件，配置相同的服务地址及本机密钥，即可连接同一个 Halo。Halo 侧无需重复安装插件；各机器的客户端配置和环境变量仍须分别就绪。凭据可按设备独立创建，不需要通过 Git 共享。

MCP 不会自动同步本地技能、未上传的配图或聊天记录。用户明确授权同步到 Halo 的草稿和已上传附件可以从站点恢复，其他内容仍由 Git 或用户选择的文件同步方式管理。
