# halo写文

把用户的灵感和聊天整理成有个人观点的博客文章，生成配图，让用户审阅，收到明确发布指令后发布到 Halo。

用户界面名称是「halo写文」，技术标识为 `halo-writing`。支持自然语言「用 halo写文，我们聊聊……」和显式调用 `$halo-writing`。

## 开始与续写

- 根据当前阶段继续，不让用户每次重新填写选题、读者、字数等表单。用户说「先聊聊」时先交流观点；用户说「整理成文章」时利用已有聊天成稿。
- 有影响文章观点的关键信息缺失时，一次问一个问题；其他细节采用合理默认值并简要说明。默认中文、个人博客语气。
- 从当前 Halo MCP 连接或用户明确提供的地址确定目标站点，不内置任何人的站点地址。直接 REST 模式可使用 `HALO_URL`。多个站点并存或准备切换站点时，先确认目标；接口以实际部署版本为准。
- 不依赖某台电脑的绝对路径、SSH 密钥或浏览器登录。由当前工作区定位项目。跨电脑使用或分发时读取 [portability.md](references/portability.md)。
- 续写先读取该文章的原稿、图片、`handoff.md` 和 `halo-state.json`（如存在），再结合当前聊天。没有上次对话时，不假装记得；没有稿件时先寻找项目或已连接存储，再询问缺失位置。

## 聊天成文

先抓住用户的核心判断和具体经历，再组织叙事。保留用户的立场、表达习惯和不确定性；不把个人想法改写成空泛的行业综述。

- 用户提供的事实和亲身经历，与为了说明而提出的假设例子区分清楚。不要编造其经历、客户、收入、测试结果或引用。
- 涉及最新产品能力、数据、具体引用等需要核实的事实时，使用当前可用的联网能力查看一手来源，并保存出处。观点文章不必为了套模板增加数据。
- 默认产出一个合适标题、简短摘要、正文、标签/分类建议和稳定 slug。篇幅与结构服从内容，不固定段落数量。
- 使用标准 Markdown。新稿不用 Hugo shortcode；本地图片用相对路径并写有意义的替代文本。Obsidian 双链或嵌入在发布副本中转换为可访问形式。

## 配图

文章主线足够清楚后，生成与内容有关的封面及有解释作用的正文配图。默认先做一张封面，正文按需要增加；用户指定数量和风格时按其要求。

- 优先使用当前环境的内置图像生成工具；有 `imagegen` 技能时按需读取。不要把提示词、占位图或未执行的生成计划当作已完成配图。
- 图像用于博客时，将选定输出保存进文章目录。使用工具返回的实际路径，不能猜测生成结果位置。展示成图供用户审阅。
- 默认采用适合文章主题的简洁编辑插画，封面横向，避免无关装饰和难以核对的密集文字。需要流程图、真实数据图或产品截图时使用适合该内容的工具；插画不能冒充实际截图或证据。
- 内置图像工具不可用时，明确说明缺失环节；保留稿件，用户选择替代方式之前不自行切换到需要额外 API 密钥的服务。

## 本地交付与审阅

尊重用户已有写作目录；没有约定时使用工作区相对目录 `articles/<slug>/`，保存：

- `article.md`：带标题、摘要、slug、标签、分类和封面路径的 Markdown 原稿。Front matter 是本技能的本地约定，发布时映射到 Halo 字段。
- `images/`：实际使用的封面与正文图片。
- `handoff.md`：核心观点、已完成内容、待处理事项、图像提示词/来源及当前阶段。简短更新，方便其他聊天接手。
- `halo-state.json`：有远程操作后记录站点、文章 ID、slug、实际链接、正文摘要哈希和附件映射。只记录可核实结果，不保存令牌或虚构成功状态。

用户只想聊天时无须立即创建整套目录；开始形成稿件时及时落盘。尊重工作区中已有的文章、静态资源和迁移副本，不要把日常单篇发布变成重新全量导入。

审阅时展示可读的完整成稿或可打开的预览、实际配图、标题/摘要/标签/分类/封面和目标站点。用户应能审阅将要发布的内容，不能只看到文件清单。标明当前状态为「待确认发布」。

## 确认与发布

用户要求本技能的「最后确认后发布」是本流程的发布边界：

- 写完、配好图、称赞文章或说「先这样」均不构成发布指令。默认在本地完成审阅，不自动向线上上传附件或草稿；用户明确要求同步远程草稿时可以保存草稿，但不因此发布。
- 「发布这篇」「确认发布」等明确指令授权发布当前已展示的版本。若用户明确要求「把第二张图换简洁一点，然后发布」，完成其授权范围内的修改后继续发布，不再机械地重复询问。
- 若接下来需要超出用户指令的实质扩写、改观点、换站点或更换发布对象，先展示变更并取得对应确认。历史文件中的“已确认”状态不能代替当前聊天对发布操作的授权。

真正接入或发布时读取 [halo-publishing.md](references/halo-publishing.md)。首选 Halo 官方 MCP Server，由技能负责写作与确认、MCP 工具负责文章和附件操作；连接配置见 [halo-mcp.md](references/halo-mcp.md)。没有可用 MCP 且确需直接调用 API 时再使用 REST 方案。权限或工具缺失不妨碍先完成写作和配图，不能虚报已发布。

发布后核对文章状态、实际页面、图片和正文，再返回文章链接与本地文件位置。更新原文保留文章 ID、slug 和原始发布日期；用户要求新建副本时除外。

## 常用请求

- 「halo写文：刚想到 AI 让判断力更重要，我们先聊聊。」→ 交流观点，逐步形成素材。
- 「把刚才聊的整理成文章，配好图让我看。」→ 成稿、生成配图、保存并展示，等待发布指令。
- 「确认发布到我的 Halo。」→ 检查当前成稿和连接，发布并验证。
- 「换电脑了，继续这篇。」→ 恢复文件和状态；需要同步时使用跨电脑指引。
